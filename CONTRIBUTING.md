# Clinic-Ease Team Contribution Guidelines

## 1. Branch Naming Conventions

All team members should create a separate branch for their assigned work.

- `feature/description` — New features
- `fix/description` — Bug fixes
- `test/description` — Testing tasks
- `docs/description` — Documentation changes

Examples:
- `feature/login-page`
- `feature/appointment-booking`
- `fix/login-error`
- `test/appointment-booking`
- `docs/setup-guide`

## 2. Pull Request Workflow

1. Create a branch from `main`.
2. Make changes on your branch and commit them.
3. Push your branch to GitHub.
4. Open a pull request targeting `main`.
5. Request a review from a teammate.
6. Test the changes and address review comments.
7. Merge only when the repository's required checks and reviews are satisfied.

Avoid making changes directly to `main`.

## 3. Code Review Responsibilities

- Reviewers should check code quality, readability, and potential errors.
- Reviewers should leave clear and constructive comments.
- Authors should address requested changes before merging.

## 4. Testing Responsibilities

- Test new features and bug fixes before requesting approval.
- Document problems found during testing.
- Fix identified issues and test again before merging.

## 5. Team Leader Responsibilities

- Maintain branch naming and pull request guidelines.
- Coordinate code reviews and testing.
- Monitor issues, pull requests, and team contributions.
- Keep the project board updated as tasks progress.
